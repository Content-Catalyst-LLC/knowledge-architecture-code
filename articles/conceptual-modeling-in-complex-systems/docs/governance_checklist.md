# Governance Checklist

## Boundary and Scope

- [ ] The model has an explicit system boundary.
- [ ] The model has spatial and temporal scale notes.
- [ ] Exclusions are documented.
- [ ] Unit of analysis is clear.

## Components and Relationships

- [ ] Components are typed.
- [ ] Components have definitions.
- [ ] Relationships are directional.
- [ ] Relationships are typed.
- [ ] Vague "related" links are minimized.
- [ ] Feedback-relevant edges are identified.

## Evidence and Uncertainty

- [ ] Relationships include provenance where possible.
- [ ] Assumptions are documented.
- [ ] Uncertainty context is visible.
- [ ] Evidence quality is noted.
- [ ] Scenario assumptions are separated from empirical claims.

## Equity and Responsibility

- [ ] Affected groups are considered where the model informs policy or planning.
- [ ] Community knowledge is not extracted or exposed without governance.
- [ ] Model exclusions and power implications are documented.
- [ ] AI-generated relationships are reviewed before use.

## Revision and Reuse

- [ ] Model versions are tracked.
- [ ] Review status is documented.
- [ ] Simulation-ready assumptions are separated from conceptual assumptions.
- [ ] Reuse conditions and limitations are explicit.
