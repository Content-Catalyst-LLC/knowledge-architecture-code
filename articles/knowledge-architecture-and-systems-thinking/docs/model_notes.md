# Model Notes: Knowledge Architecture and Systems Thinking

## Core Idea

Knowledge architecture and systems thinking meet where knowledge is treated as a living system of objects, relationships, feedback loops, assumptions, boundaries, flows, revisions, and governance processes.

## Core Layers

1. **Boundary layer**
   - system boundary
   - adjacent context
   - disciplinary context
   - platform scope
   - access boundary
   - governance boundary

2. **Knowledge-object layer**
   - articles
   - article maps
   - concepts
   - frameworks
   - evidence records
   - models
   - decisions
   - outcome indicators
   - revision logs
   - AI retrieval records

3. **Relationship layer**
   - organizes
   - usesEvidence
   - supportsModel
   - informsDecision
   - monitoredBy
   - feedsBackTo
   - revises
   - retrieves
   - flagsGapFor
   - governs

4. **Feedback layer**
   - user feedback
   - evidence update
   - repository validation
   - editorial review
   - governance review
   - AI retrieval correction
   - outcome-to-revision loops

5. **Scale layer**
   - source
   - concept
   - article
   - domain
   - institution
   - platform
   - system
   - global

6. **Assumption layer**
   - category assumptions
   - relationship assumptions
   - evidence hierarchy
   - system boundary
   - AI retrieval assumptions
   - governance assumptions

7. **Governance layer**
   - review checks
   - metadata standards
   - access rules
   - correction pathways
   - revision history
   - AI-assisted workflow review

## Key Review Questions

- Are knowledge-system boundaries explicit?
- Are knowledge objects typed?
- Are relationships typed and traceable?
- Do major knowledge objects participate in feedback loops?
- Is scale documented?
- Are assumptions and mental models visible?
- Are revisions and governance records preserved?
- Can AI retrieval use provenance and relationship context responsibly?
