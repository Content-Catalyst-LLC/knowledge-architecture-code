# Governance Checklist

## Metadata

- [ ] Every article has title, slug, category, series, focus keyword, tags, and excerpt.
- [ ] Every repository-supported article has a repository path.
- [ ] Every dataset has a data dictionary.
- [ ] Every output identifies the script or method that generated it.

## Repository Alignment

- [ ] Article folder names match article slugs.
- [ ] Repository README files explain purpose and scope.
- [ ] Repository data files are synthetic or clearly documented.
- [ ] Outputs are reproducible or accompanied by expected-output records.

## Semantic Structure

- [ ] Relationship types are controlled and documented.
- [ ] Concepts are distinguished from articles, sources, methods, datasets, outputs, and repositories.
- [ ] Article-map structure aligns with taxonomy and metadata.
- [ ] Related articles reflect conceptual proximity rather than random linking.

## Evidence and Provenance

- [ ] Sources are linked where possible.
- [ ] Claims are tied to evidence or framed as conceptual interpretation.
- [ ] Relationships include provenance notes.
- [ ] Revision history is preserved for major infrastructure changes.

## AI Retrieval Governance

- [ ] AI retrieval context includes metadata and provenance.
- [ ] Retrieval distinguishes published, planned, draft, and deprecated objects.
- [ ] Synthetic datasets are not treated as empirical evidence.
- [ ] Sensitive or community-governed knowledge is not treated as automatically open.

## Equity and Epistemic Responsibility

- [ ] Classification terms are reviewed for bias.
- [ ] Alternate labels and contested terms are documented where relevant.
- [ ] Marginalized voices and archival silences are considered in platform design.
